## 一、开发纪律（动手前必读）

1. **方案先行**：任何开发任务先出方案（改动范围 / 接口设计 / 影响面 / 验收标准）并经确认，再动手写代码。
2. **算子插件化优先**：新推理算子默认做成节点自注册的服务端插件（节点包自带算子文件 + 按需上传），
   不动服务端核心；只有扩展核心原语、加载层或新对象类型时才改服务端本体。采样循环差异只进适配点，
   不做统一抽象（第三个架构出现前不重构）。
3. **真机验收才算完成**：本机（手机 Termux）无 GPU，代码落地不算完成——推理路径必须在 GPU 主机上
   实测通过才标 ✅。三条硬口径：
   - **验收必须落盘**：e2e 流水线末端必须有落盘节点写文件；对象仓库是内存态 + 4 小时 TTL，服务重启即清空。
   - **必须抽图看图**：状态全绿 ≠ 内容正确（历史教训：出片全是噪声废片但流程 success）。
   - **判据自省**：能用逐字节就用逐字节，不能才退到结构/统计 + 人眼物料。多次踩坑的真因是
     **判据口径错**而不是产物坏；改判据必须说明为什么。
4. **改完必跑门禁**（缺一不可）：节点包一致性（算子族 ↔ 节点）、控件 DOM 回归、参数一致性
   （节点参数与清单必须对齐）、节点入口桩冒烟（新增门禁，防参数改名/调用签名漂移）、共享件同步校验、
   控件全量重建校验。**新增门禁必须带负例自检**（摘掉被测修复后该门禁必须失败）。
5. **改了共享件必须重导节点**：Studio 跑的是导入时的节点包快照，共享库改了不重导等于没改；
   节点导入有频率限流，全量重导必须节流。新增节点必须先重建控件产物再导入。
6. **改了就必须活体验证**：凡改插件加载/热更新/上传等运行时路径，必须在真机跑一次端到端活体检查
   （含"同文件名重传"这类边界）；只跑单测不算。
7. **版本与钉版纪律**：算子身份 = 实现内容（内容变则名下版本戳变，新旧并存、运行期钉版）；
   节点包版本被流水线引用钉住，改节点要同步升级存量流水线的引用；镜像版本号与节点清单联动。
8. **硬件假设永不进算子逻辑**；一处 workaround 配一个开关；不确定就先做可逆的小步。

## 二、已完成能力快照（截至 2026-10-13）

规模：**节点包 104 个 / 服务端算子 108 个 / 流水线 44 条**；节点镜像版本 1.16.0。

### 基础设施（阶段 0 起）
- 异步任务体系：提交 / 轮询 / 协作式中断 / 逐步进度 / 预览帧；单 worker 串行 + 全局执行锁。
- 模型分派：按目录与权重头部嗅探架构，管道类由 diffusers 承接，引擎零改动；支持 SD1.5 / SDXL /
  SD3.5 / FLUX.1-schnell（GGUF 量化路线）/ AnimateDiff / SVD 视频。
- 显存治理：常驻模型 LRU + 显存预算 + 三档 offload + 失败自愈；**加载旋钮全量化**（dtype / offload /
  量化）与**执行租约 pin**（一次执行期间其模型不被顶掉）均已交付。
- 对象仓库：图像 / 蒙版 / latent / 视频 / 条件 / 模型句柄等对象类型，内存态 + TTL + 下载端点。
- 节点 UI 公共件化：控件基座单一事实源，全部节点带自定义 UI（细粒度拆分是既定决策）。
- 画布增强：过程/结果可视、参数来源标注、执行器状态徽章、蒙版手绘编辑器、搜索与大列表治理。

### 生成与条件控制
- 图生图/文生图全链（VAE 编解码、采样器与 sigma 排布解耦、分段采样、区域条件、局部重绘、hires fix）。
- ControlNet（加载/应用 + 采样循环逐层注入）与预处理器族；IPAdapter（SD1.5 + SDXL vit-h）、Redux、
  LoRA、Embedding、InstantID（身份保持，含人脸几何修复）；面部局部精修联动。
- 视频线：AnimateDiff 文生视频（含根因修复 + 内容级验收）、SVD 图生视频、视频落盘与播放控件。

### 图像增强（ComfyUI 对标缺口 G1~G11，B1~B5 批次）
- **传统后处理**：亮度/对比度/色相/曲线/模糊/锐化/噪点/通道等滤镜族、扩画布（outpaint）、
  预处理器补齐（线稿/软边缘/法线/直线/涂鸦/分割等）。
- **抠图与人脸**：BiRefNet 抠图（三变体 + 去白边专项）、GFPGAN 与 RestoreFormer 人脸修复。
- **分割与超分**：SAM 交互/自动分割、文本提示检测分割、分块重绘超分（含接缝融合与权重归一）。
- **上色 / 重打光 / 电商**：DDColor 老照片上色（四变体）、IC-Light 重打光（前景+背景+光照方向）、
  水印节点、白底商品图 / 场景图 / 模特规格三条电商模板流水线。
- **批量与拼图**：批量加载、批量落盘、联系表拼图三件套（Studio 无循环概念，"批量"落在 I/O 与拼图上）。

### 工程与质量
- **算子身份版本化**（算子名 = 实现内容 hash，新旧并存、零服务端改动）。
- 门禁四道（算子族一致性 / 控件 DOM 回归 / 参数一致性 / 节点入口桩冒烟）
  + 两项一致性校验（共享件同步、控件全量重建）；落地复核脚本 7 个（上色 / 电商 / 重打光 / 批量 /
  去白边 / 分割 / 分块超分）+ 运维工具 2 个（旧版本清理、产物索引）。
- 服务端插件归属簿修复（幽灵归属不再误判冲突、陈旧算子可摘除、回滚补齐模块清理、缺失文件可观测）
  与插件热更新失效修复（同文件名重传会命中旧字节码）。

## 三、待办计划

### P0：价值明确、依赖已就绪
1. **G11 补齐：环境投影节点** —— 电商链路里唯一没做的节点（商品投影：位移 + 模糊 + 透明度）。
   配套可加"白底商品换背景 / 模特换装"模板流水线（抠图 + 合成 + 投影 + 细节重绘）。
2. **FLUX 三个加载节点的 docker 执行器落地** —— 节点代码已异步化并验证，但节点镜像版本号未升、
   镜像未重建、清单未同步，**docker 执行器跑的仍是旧代码**。做法：升节点镜像版本 → 重建 → 同步清单 → 真机复跑。
3. **剩余同步算子异步化** —— FLUX 编解码与空 latent 仍是同步调用（秒级到一分钟）。判据：
   任何可能"分钟级不出字节"的算子一律改走任务式调用，不要靠调大超时（隧道掐的是连接不是超时值）。
4. **exec 686 事故复跑** —— 该失败跑留在历史里不重写快照（含旧版节点引用）。整跑对应流水线即可关闭；
   前置：GPU 主机的隧道客户端在线、本机到推理服务通道探测通过。

### P1：值得做，需先出方案
5. **错峰加载原语沉淀** —— 编码器产物落对象仓后立刻释放编码器，形成可复用的节点范式。
6. **显存策略运维节点** —— 读写服务端淘汰策略配置（当前无该端点，需先加）；定位是单流水线串行时的策略实验工具。
7. **门禁扩展：服务端算子族桩冒烟** —— 节点的入口桩冒烟已覆盖 104 个节点包，但服务端算子族里的算子函数
   尚无同类冒烟；补上可挡住参数改名类漂移。
8. **InstantID 调参扫描** —— 权重 × 结构强度的受控扫描（模型热后每点约 6 分钟），用于给出推荐档位。

## 五、环境与约束速查（计划可行性依赖）

- **硬件**：GPU 主机 = GTX 1080 8GB（Pascal，算力 6.1）+ 16GB 物理内存；开发机 = 手机 Termux，
  无 GPU、无 numpy（节点侧纯图像处理节点必须零 numpy，否则本机无法单测、问题只能到真机才暴露）。
- **Pascal 钉版**：torch 2.3.1 / diffusers 0.35.2 / transformers 4.44.2 / numpy < 2；
  **算力低于 7.0 默认走 fp32**（该卡非张量 fp16 吞吐极差）。新增依赖要同步改两个依赖清单与镜像。
- **权重要放宿主机** `D:\flowx-data\models`（C 盘空间是硬约束）；**从 Windows 绑定挂载读权重极慢**
  （数 GB 模型冷加载可达数十分钟）⇒ 重链路开跑前先确认模型是否已常驻。
- **通道**：隧道地址每次重建都会变，**禁止写死，动手前先确认当前地址**；手机离开局域网时
  本机只读链路（落盘节点）会失效，但容器内网路径仍可用；大文件传输走宿主机直下。
- **服务端**：单 worker 串行（并发提交只会排队）；对象仓库内存态 + 4 小时 TTL，**重启即清空**；
  失败/中断的执行会留下租约钉住模型，过期自动释放。**默认不重启推理服务**（改环境变量 / 换镜像 /
  改部署配置前必须先取得同意）。
- **插件上传语义**：同文件名不同内容 = 覆盖更新；不同文件抢同一算子 = 冲突并全量回滚；
  显式接管可强推。归属簿只在"上传"与"启动扫描"两处写入（这是幽灵归属类问题的根源）。
- **验收物料**：每批产出人眼可看的联系表（总览图 + 手机图集），并保留可检索的产物索引。
